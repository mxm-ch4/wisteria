# SPEC_POLISH.md — медиа без PowerShell и SeedcrackerX

> По прямой команде владельца. Одна сессия, Opus, отдельный коммит и пуш после зелёного шлюза на каждую часть. Отчёт не больше одной страницы.
> Правила: A5.1 §8 (всё через меню), STEALTH (`docs/privacy.md`), SPEC_PASSIVE «ноль лишних пакетов». Идёт до SPEC_INSTALLER.md и SPEC_RELEASE.md.

## 1. Медиа-виджет без PowerShell
Причина: запуск PowerShell из Java выглядит подозрительно для антивируса и для пользователя.
- Доступ к системному API медиа Windows (SMTC) **внутри процесса игры**, без дочерних процессов, без окон консоли. Предпочтительно Java FFM (`java.lang.foreign`, JDK 25), вызовы COM и WinRT через вручную описанные интерфейсы. Если игровой JNA удобнее, допустимо.
- Проба в начале (в отчёт полстраницы): что выбрано, как проходит предупреждение о нативном доступе в консоли игры (должно быть максимум одной безвредной строкой), чем описаны интерфейсы.
- Если внутрипроцессный вариант не получился: оставить помощник, но запускать только после включения виджета владельцем (по умолчанию выключен), без окна (`CREATE_NO_WINDOW`), с `-NoProfile -NonInteractive`, и честно отметить это в отчёте и в `docs/media.md`.
- Источник данных за интерфейсом остаётся, тесты идут на поддельном источнике. Живая проверка владельцем описана в `docs/media.md`.
- Никаких сетевых запросов.

## 2. SeedcrackerX
Факты (проверено на странице проекта): версия 2.16.1 помечена под 26.2, лицензия MIT, в README есть раздел «API for other mods»: интерфейс `SeedCrackerAPI` с методом `pushWorldSeed(long seed)`, регистрация как entrypoint `seedcrackerx` в `fabric.mod.json`.
- Проверить, откуда брать артефакт API для 2.16.1 (JitPack, или он внутри мода). Если артефакта нет: вендорить один интерфейс как отдельный файл с MIT-атрибуцией и сохранением имени пакета (нужно для entrypoint).
- Реализовать мягкую интеграцию: если SeedcrackerX установлен, найденный сид автоматически попадает в Client → Seeds для текущего сервера (SeedStore), с локальной пометкой «получен от SeedcrackerX». Если не установлен, ничего не меняется. Обязательной зависимости нет, `fabric.mod.json` не требует его.
- Ничего не отправляется по сети. Аудит сети остаётся с нулём лишних пакетов.
- Тест: подставной вызов `pushWorldSeed` в игровом тесте приводит к записи сида для сервера; повторный вызов с другим сидом не затирает ручной без подтверждения в меню.
- Если на 26.2 интеграцию проверить нельзя, закончить модульными тестами и отметить «нужна живая проверка».

## Готово, когда
Медиа работает внутри процесса (или честно описанный запасной вариант); SeedcrackerX передаёт сид через API (или честная пометка); шлюз зелёный; аудит сети без лишних пакетов.

Установщик вынесен в `SPEC_INSTALLER.md` и делается **после всех функций**, отдельной командой.
