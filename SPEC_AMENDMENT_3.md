## 1. Постановка (честная)

**«Обойти» Paper anti-xray на стороне клиента нельзя**: скрытые блоки сервер просто не присылает (в режиме 1 руды, полностью закрытые твёрдыми блоками, подменяются; в режиме 2 и 3 дополнительно подмешиваются фейковые руды). Любые «обходы по пакетам» это баги конкретной версии, живут недели и мы на них не строим.

**Что реально работает: предсказание по сиду.** Генерация руд детерминирована сидом и версией. Если сид известен, клиент считает, где руды должны быть, не опираясь на присланные чанки. Это одновременно «обходит» anti-xray и отличает фейки режима 2/3 от настоящих.

Ограничения (записать в README и в GUI):
1. Работает только для чанков, сгенерированных ванильной генерацией **той же версии**, что считает клиент. Старые чанки (сгенерированные в прошлых версиях, как на 2b2t) и кастомная генерация (датапаки, плагины) дают неверные предсказания.
2. Блоки, изменённые игроками (выкопанные, поставленные), отличаются от предсказания.
3. Нужен сид. Его либо знают (свой сервер, публичные сиды), либо находят (раздел 3).

## 2. Xray: два слоя

В Xray Quality (AMENDMENT_2 §3) добавить второй источник данных:

| Слой | Источник | Метка в GUI |
|---|---|---|
| **Server** | Что реально пришло от сервера | сплошной контур |
| **Predicted** | Расчёт по сиду | пунктирный контур + «уверенность» |

Режимы:
- **Fake detector:** ore, пришедшая от сервера, но не совпавшая с предсказанием, помечается как вероятный фейк (режим 2/3). Предсказанная, но не пришедшая — как скрытая жила.
- **Hidden vein ESP:** подсветка предсказанных скрытых жил (то, что сервер маскирует).
- **Confidence:** отдельный цвет/прозрачность по степени уверенности (высокая для свежих ванильных чанков, низкая, если чанк помечен «старой версией» или детектором изменений).
- Интеграция с Baritone: «выкопать предсказанную жилу» через Tunneler/Ore tracker (PVE_BACKLOG №4, №13).

## 3. Seed Intel

Модуль-хранилище и источник сида.

1. **SeedStore:** сид на сервер/мир (ключ: адрес сервера + измерение), хранится локально в файле конфигурации клиента, не в репо. Ручной ввод командой.
2. **Взлом сида по наблюдению (SeedcrackerX-подход):** сид восстанавливается по собранным данным структур и декораций, и это быстрее, если рядом есть подходящие структуры. Открытая реализация есть (MIT). У неё есть API для интеграции в другие Fabric-моды (точка входа `seedcrackerx` в `fabric.mod.json`).
   - **Этап 0:** проверить, поддерживает ли актуальная версия SeedcrackerX Minecraft 26.2 (по поиску подтверждения не нашёл; документация говорит про 1.18+). Если нет: либо ждать/форкнуть, либо делать свою реализацию (L, отдельная задача).
3. **Проверка кандидата по hashed seed:** клиент получает от сервера хэш сида (по общему знанию, это часть пакета входа). По нему можно быстро отсеивать неверные кандидаты. Уточнить формат на этапе 0 живым тестом.
4. **Публичные сиды:** для серверов с известным сидом (например, 2b2t) поиск не нужен, только ввод и пометка «ограничение: старые чанки» (см. §1).

## 4. Генерация руд: как считать

Варианты (выбрать на этапе 0):

| Вариант | Идея | Плюсы | Минусы |
|---|---|---|---|
| A. Зависимость от SeedMapper | Использовать его как опциональную зависимость/библиотеку | Уже есть биомы, структуры, руды, лут; сборка под 26.2 есть. LGPL-3.0+ совместима с нашим GPL-3.0 | Нужно проверить, есть ли у него пригодный API; завязка на чужой цикл релизов |
| B. Свой слой через cubiomes | Подключить cubiomes (C) к нашему коду | Полный контроль, нужные нам форматы | Нативные библиотеки под каждую ОС (Windows/Linux/macOS), CI для сборки; **лицензию cubiomes проверить** |
| C. Чистый Java | Своя реализация генерации | Без нативки | Долго, легко ошибиться, версии |

Рекомендация для этапа 0: попробовать A (быстрее всего получить рабочий Xray Predicted), параллельно прикинуть B. В Java 25 есть стабильный Foreign Function & Memory API, поэтому вызывать cubiomes можно без JNI-обвязки, но бинарники под ОС всё равно нужно собирать и подписывать.
Версионность: слой генерации привязан к версии игры. Через `compat/` (AMENDMENT_2 §1): `OreGenBackend` с реализациями по версиям, на неподдержанной версии модуль выключен, а не врёт.

## 5. Тестовый харнесс (на стенде владельца)

Сид на своём сервере владелец знает, поэтому проверка точная:

1. Включить Paper anti-xray (поочерёдно режимы 1, 2, 3) в тестовом мире.
2. Эталон: отключить anti-xray, прогнать Xray по области, сохранить реальные руды в файл (`docs/oregen-ground-truth.csv`).
3. Включить anti-xray, прогнать Predicted, сравнить с эталоном: доля найденных, доля ложных (precision/recall). Результат в `docs/oregen-eval.md`.
4. Отдельно проверить: (а) мир, сгенерированный на той же версии, (б) область со старой версией генерации, (в) область с изменёнными игроками блоками. Это покажет реальные границы точности.
5. Проверка детектора фейков: на режимах 2/3 доля корректно помеченных фейков.
