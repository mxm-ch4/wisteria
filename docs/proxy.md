# Прокси и профили

Чтобы сервер по IP не мог связать один аккаунт с другим. Клиент **не даёт анонимности**: он убирает только связку по IP
и не даёт данным разных профилей смешиваться. Аккаунт и вход в Minecraft остаются на стороне лаунчера.

Всё настраивается в ClickGUI, панель **Client** (чат-команды — по желанию, они только дублируют меню).

## Прокси

**Client → Proxy.** Включённый раздел значит: этот профиль подключается к серверам только через выбранный прокси.

| Что | Как |
|---|---|
| Добавить | поле **Proxies**: `имя socks5 host:port` или `имя http host:port`, кнопка Add |
| Выбрать | список **Proxy** |
| Логин и пароль | поля **Login** и **Password**: ввод скрыт точками, Enter сохраняет; хранятся в `.minecraft/wisteria/.env` (`PROXY_<ИМЯ>_USER`, `PROXY_<ИМЯ>_PASSWORD`), не в конфиге, не в чате, не в логе; из чата не принимаются |
| Проверить | **Test**: запрос через прокси к сервису **IP Service** (по умолчанию `api.ipify.org`), в чат — адрес, который видит мир. Хост сначала разрешить в **Client → Network** |
| Удалить | минус у строки в списке; логин и пароль удаляются вместе с ним |

- **SOCKS5** (с логином или без) и **HTTP CONNECT**, через Netty-обработчики `netty-handler-proxy` и `netty-codec-socks`
  (Apache-2.0): в игре их нет, поэтому они вложены в jar клиента.
- **Имя сервера резолвит прокси** (SOCKS5 с удалённым DNS, у HTTP — `CONNECT host:port`): клиент сам ничего не
  ищет — ни DNS, ни **SRV-записи**. Значит, при включённом прокси адрес вида `play.example.com` без порта
  подключается на 25565, а не туда, куда указала бы SRV-запись; если сервер живёт на SRV, вводите `host:port`.
- **Без утечек.** Если раздел включён, а прокси не выбран, удалён или не отвечает — соединение блокируется,
  на прямое подключение клиент не переходит. Причина видна на экране «Не удалось подключиться» и тостом в HUD.
  То же для пингов списка серверов: они идут через прокси или не идут вовсе.
- **Индикатор** — HUD-элемент **Proxy Status**: «Proxy: имя (host:port)», «blocked» или предупреждение «Proxy off: direct».

## Что ещё выдаёт адрес

| Трафик | Что делает клиент |
|---|---|
| Соединение с сервером, пинги списка серверов | через прокси или заблокировано |
| **Ресурспаки сервера** | игра качает их по ссылке напрямую, а хост ссылки может видеть адрес. С включённым прокси по умолчанию пак **отклоняется** (серверу уходит «declined») с сообщением в чат. **Server Packs → Accept** — принимать как обычно (адрес виден хосту пака). Скачивание через прокси не сделано |
| Сеть Wisteria (`Net`, будущий Notifier) | **выключена**, пока включён прокси |
| Вход в Minecraft, скины (Mojang/Microsoft) | идут напрямую: это не сервер, но знать об этом стоит |

## Профили

**Client → Profiles.** Профиль — это настройки модулей, выбор прокси и своя папка данных.

- Папка данных: `.minecraft/wisteria/profiles/<имя>/` (`data/<модуль>/`, `exports/`). Переключение профиля
  переключает и данные: находки одного профиля в другой не попадают.
- **Profiles → Add** создаёт **пустой** профиль: настройки по умолчанию, без данных, без прокси. **Save As**
  копирует только настройки текущего (не данные). **Active** переключает.
- Секреты по профилям: в профиле `default` — `ИМЯ`, в профиле `twink` — `ИМЯ@twink`. Чужие ключи не подставляются.
- Друзья и враги — общие для всех профилей.

## Всё через меню

Сообщение в чате может уйти на сервер (опечатка, сбой), поэтому:

- у каждой команды есть контрол в ClickGUI; тест перечисляет все команды и падает, если какой-то нет;
- всё, что начинается с префикса, **никогда не уходит на сервер**: неизвестная команда, ошибка, один только префикс,
  выключенные чат-команды (**Client → Chat → Chat Commands**) — клиент гасит строку и пишет пометку себе;
- секреты вводятся только в полях-паролях, ни одна команда не принимает их аргументом.

## Как проверено

- **Модульные тесты:** разбор прокси, маршрут (выключено — напрямую; включено без выбора или удалённый — блок),
  логин и пароль только в `.env` (ни в одном JSON их нет), удаление забывает логин, отказ принять пароль из чата,
  сеть клиента выключена при прокси, проверка требует разрешённого хоста; туннель SOCKS5 с логином (имя сервера
  уходит именем) и HTTP CONNECT с авторизацией; мёртвый прокси — ошибка, не прямое соединение; профили (пустой новый,
  своя папка данных, переключение туда и обратно, секреты по профилям); префикс в чате; паритет команд и меню.
- **В игре** (`ProxyGameTest`): настоящий выделенный сервер на этой машине и тестовый SOCKS5, который выходит
  с адреса 127.0.0.2. Напрямую сервер видит 127.0.0.1, через прокси — 127.0.0.2, а прокси получил имя
  `localhost`, а не адрес. Прокси остановлен — до сервера не дошло ничего.

Не проверено вживую: настоящий внешний прокси и сервер с AuthMe; отклонение ресурспака — только модульно.
