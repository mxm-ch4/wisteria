# SPEC_RELEASE.md — последняя задача: чистка публичного репо

> Отдельная задача. Берётся только по прямой команде владельца и только когда все остальные задачи сделаны и приняты. Одна сессия, Opus, отчёт не больше одной страницы.
> Цель: репозиторий для публики выглядит как обычный проект автора. В нём нет следов процесса разработки (инструменты, спеки, рабочие заметки) и нет личных данных владельца.
> Claude Code **ничего не пушит и не создаёт репозитории**. Он готовит чистую папку, дальше всё делает владелец сам.

## 2. Порядок работы

1. Создать папку `../wisteria-release/` рядом с рабочей копией. Рабочую копию не менять.
2. Скопировать туда только то, что нужно для сборки и использования: `src/`, `docs/` (после §5), `README.md`, `LICENSE`, `LICENSE_fonts.txt`, `build.gradle`, `settings.gradle`, `gradle.properties`, `gradle/`, `gradlew`, `gradlew.bat`, `.gitignore`, `.gitattributes`.
3. Пройти чистку по таблице §1. Код менять минимально: только комментарии, строки и метаданные. Поведение не трогать.
4. Выполнить проверки §6. Любое срабатывание чинится и проверки гоняются заново.
5. Приватный архив (§3) собрать в `../wisteria-private/`.
6. Отчёт: что убрано (по категориям, числами), результаты проверок, что владельцу сделать руками (§4).

## 3. Приватный архив

В `../wisteria-private/` (вне репо, не в облаке, не под git) уходит всё, что не должно быть публичным, но нужно владельцу:

- все спеки и амендменты, бэклог, `CLAUDE.md`, `.claude/`;
- технические разборы (`stage0-findings.md`, `grim-matrix.md`, `grim-alert-format.md`), если владелец хочет их сохранить;
- список того, что было удалено из релиза, одной таблицей (файл, причина).

Эти файлы содержат контекст про личные серверы, прокси и разбор чужих античитов, поэтому публичными быть не должны.

## 4. История и новый репозиторий

Переписывание истории существующего репо (rebase, filter-repo) оставляет следы: старые SHA остаются достижимыми через форки, кэши и закэшированные ссылки на коммиты. Поэтому надёжный путь только такой, делает его **владелец**, Claude Code лишь готовит папку:

1. Владелец делает текущий репозиторий **приватным** (Settings → General → Danger Zone → Change visibility). Это можно сделать сразу, не дожидаясь релиза.
2. Владелец проверяет `../wisteria-release/` сам (глазами, §6).
3. Владелец создаёт **новый** репозиторий и делает **один** начальный коммит от своего имени. Рекомендуется адрес GitHub noreply (`ID+имя@users.noreply.github.com`), а не личная почта. Перед коммитом: `git config user.name` и `git config user.email` в этом репо, затем `git commit` вручную. Трейлеры ИИ-инструмента не добавляются, потому что коммит делает человек, а не сессия.
4. Старый репозиторий владелец удаляет или оставляет приватным.
5. Claude Code в релизной папке **не выполняет** `git commit` и `git push`: его сессия добавляет трейлеры автоматически, а это и есть то, что мы чистим.

Честно про предел: что уже было публично, могло быть склонировано или заархивировано сторонними сервисами (веб-архивы, зеркала, форки). Полностью стереть это нельзя, можно только перестать публиковать.

## 7. Нейтральные имена в релизной сборке

Цель: в файлах и логах на компьютере владельца нет слова «wisteria», если он не захочет его оставить. Это про приватность на своём ПК (общий компьютер, посторонний взгляд на папки), к серверу отношения не имеет: протокол Minecraft не даёт серверу видеть локальные файлы.

| Где встречается имя | Что делаем |
|---|---|
| Папка данных `.minecraft/wisteria` | Имя берётся из одной настройки сборки (`dataDirName`), по умолчанию нейтральное. Миграция: если старая папка есть, при первом запуске переносится |
| Имя jar | Из свойства сборки (`jarName`), без слова клиента по умолчанию |
| `fabric.mod.json` (id, name, описание, иконка) | Из свойств сборки: `modId`, `modName`. Пути ассетов и пространство имён ассетов следуют `modId` |
| Пакеты Java и имена миксин-конфигов | Переименование пакета `dev.wisteria` на нейтральный через одну команду Gradle (без ручной правки), тесты зелёные после переименования |
| Строки в логах игры (`latest.log`), краш-репорты | Клиент не пишет своё имя в лог; имя в списке загруженных модов определяется `modName` |
| Заголовок окна, водяной знак, главное меню, название профиля лаунчера | Название бренда в интерфейсе настраивается в меню (Client → Interface), по умолчанию из `modName` |
| Запись в Mod Menu | Не регистрируем |

- Свойства сборки: `gradle.properties` или `-P`. Разработческая сборка остаётся как сейчас, нейтральная включается свойством `neutral=true`.
- Проверка: после сборки с `neutral=true` поиск по jar, по папке данных после запуска и по `latest.log` не находит слова клиента. Результат в отчёт.
- Не делаем: скрытие файлов от проверки, подмену системных атрибутов, автоудаление следов по сигналу. Это уже не приватность владельца, а обход проверок на серверах, где они требуются.
