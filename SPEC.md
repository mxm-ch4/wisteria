## 1. ЦЕЛЬ И РАМКИ

Утилити-мод под Fabric для Minecraft Java. **Изменено (AMENDMENT_2 §1):** основной таргет (Tier 1) — **26.2**:
полный функционал, живые тесты, Grim-матрица. Tier 2 — **26.3 и 26.1.x**: билд собирается, клиент стартует,
smoke-тест. Версия считается поддержанной, только если на ней зелёный шлюз `tools/gate.sh`; состояние — в `docs/version-matrix.md`.
Главный упор — **дизайн и визуал**: собственный GUI, HUD, анимации, тема, встроенный проигрыватель музыки. Логика модулей — вторична по времени, но критична по качеству (обход Grim на 2b2t).

Целевой сервер — 2b2t (через ViaVersion принимает клиенты версии сервера и новее). Античит — Grim.

**Вне рамок:** продажа как закрытого продукта на чужом GPL-коде (см. раздел 11). Любая автоматизация-макросы, за которые банят на 2b2t.

## 2. СТЕК

**Изменено по итогам этапа 0** — версии, на которых проект реально собирается и проходит шлюз (`docs/stage0-findings.md`).

- Minecraft: 26.2 (Tier 1); 26.3 и 26.1.2 (Tier 2)
- Loader: Fabric Loader **0.20.1**, Fabric API своя на версию (`compat/v26_x/gradle.properties`)
- Сборка: Fabric Loom **1.19.4**, Gradle **9.8.2**, Java **25**
- Маппинги: Mojang official. 26.1+ не обфусцирован → Yarn НЕ используем, remapping отключён
- Мульти-версия: обычный мульти-проект Gradle. `core/` — логика без Minecraft в classpath; `compat/common` — общая
  реализация; `compat/v26_x` — отличия версии. Один репозиторий, один исходник логики, N jar на выходе
- **Правило:** модули, GUI, HUD и ядро не вызывают игру напрямую — только через интерфейсы `dev.wisteria.compat`
  (`Renderer2D`, `Renderer3D`, `InputBackend`, `AudioBackend`, `PacketAdapter`, `ScreenBackend`). Прямой вызов из `core/` не компилируется
- Рендер: **через рендер-API игры, НЕ сырой OpenGL**. С 26.2 в игре есть Vulkan; шлюз гоняется на обоих бэкендах
- Pathfinding: Baritone — есть официальные релизы под 26.1, 26.2, 26.3
- Язык: Java

## 4. ЭТАП 1 — ЯДРО

Каркас, на который вешается всё. Без GUI-красоты пока, голая функциональность.

- `ModuleManager` — реестр модулей, вкл/выкл, категории
- `Module` — базовый класс: имя, описание, категория, bind-клавиша, onEnable/onDisable/onTick
- `SettingsAPI` — типы настроек: bool, slider (int/float/double), enum, color (RGBA), keybind, string. Каждая настройка сериализуется
- `EventBus` — подписка на события из этапа 0 (tick, render2D, render3D, packet, key)
- `ConfigManager` — сохранение/загрузка в `.minecraft/<client>/` (JSON). Профили конфигов (несколько пресетов)
- `CommandManager` — чат-команды с префиксом (`.`), автодополнение
- `Friends` + `Enemies` — списки, используются модулями таргетинга

**Контроль:** 2–3 тестовых модуля (например FullBright, тестовый HUD-текст, тестовый ESP-бокс) включаются с клавиши и из команды, настройки сохраняются между перезапусками.

## 5. ЭТАП 2 — ДИЗАЙН-СИСТЕМА (сердце проекта)

До рисования GUI — зафиксировать систему, чтобы весь клиент выглядел как одно целое, а не набор окон.

Создать `docs/design-system.md` и код-константы:

- **Палитра.** База (тёмная), поверхности, акцент (`<<< лавандовый >>>`), градиенты, состояния (hover/active/disabled), семантика (вкл=акцент, выкл=приглушённый). Светлая тема — опционально, но закладываем структуру.
- **Типографика.** Кастомный шрифт (TTF в ресурсах, рендер через шрифт-рендерер игры/свой атлас). Размеры: заголовок, модуль, подпись, моно для цифр. Кернинг/межстрочный.
- **Спейсинг.** Шкала отступов (4/8/12/16), радиусы скругления, толщина обводок.
- **Motion.** Единая система анимаций: easing-функции (easeOutCubic и т.п.), длительности (быстрая 120мс, обычная 200мс, медленная 350мс), интерполятор с дельта-тик. Всё анимированное дёргает один `Animation`-хелпер, а не самописные лерпы в каждом месте.
- **Эффекты.** Blur за панелями (если рендер-API 26.2 позволяет — проверить в этапе 0), тени, glow вокруг акцента, скруглённые прямоугольники с антиалиасингом. Шейдеры — только если переживут Vulkan.

**Контроль:** страница-демо (debug screen) со всеми компонентами палитры, шрифтов, анимаций.

## 6. ЭТАП 3 — GUI (ClickGUI + меню)

Главный визуальный артефакт. Строится ТОЛЬКО на дизайн-системе из этапа 2.

- **ClickGUI:** категории модулей, карточки модулей, раскрытие настроек, drag панелей, скролл, поиск модуля по имени
- Компоненты: кнопка, тумблер, слайдер, дропдаун, color-picker (HSV + alpha + hex-ввод), keybind-биндер, текст-поле
- Анимации: плавное открытие меню, hover-переходы, раскрытие настроек, pressed-состояния — всё через motion-систему
- **Темы:** пользователь переключает акцент/пресеты темы в рантайме, мгновенно применяется
- Отдельный **стартовый экран / splash** при запуске (лого, версия) — для «вкусности»
- Главное меню игры перерисовать под бренд (опционально, этап можно отложить)

**Контроль:** всё меню управляется мышью/клавой без визуальных багов, 60+ fps с открытым GUI, темы переключаются вживую.

## 7. ЭТАП 4 — HUD

- `HudManager` + перетаскиваемые элементы с привязкой к краям (anchor) и редактором расположения
- Элементы: ArrayList модулей (с анимацией появления/исчезновения и градиентом), Watermark (лого+fps+пинг), координаты, направление/биом, FPS, TPS-метр сервера, таргет-инфо (HP цели), PotionHUD, Notifications (тосты на событиях), KeybindList
- Всё в стиле дизайн-системы, анимированное
- Редактор HUD: отдельный экран, сетка-привязка, снап к другим элементам

**Контроль:** элементы двигаются, привязываются, позиции сохраняются в конфиг.

## 8. ЭТАП 5 — МУЗЫКА / АУДИО

- **Встроенный плеер:** проигрывание своих треков (ogg/mp3→ogg) из папки `.minecraft/<client>/music/` или из ресурсов
- Управление: play/pause/skip/prev, громкость отдельно от игрового звука, шаффл, луп
- **HUD-виджет плеера:** обложка, название трека, прогресс-бар, кнопки — в стиле дизайн-системы, анимированный
- Хоткеи на управление
- Опц.: визуализатор (бары по амплитуде) в HUD — только если рендер-бюджет позволяет
- Звуки интерфейса: клик, hover, toggle, уведомление — свой звуковой набор (опционально)

**Контроль:** трек играет, не конфликтует с игровым звуком, виджет показывает прогресс, громкость независимая.

- Логика из GPL-клиентов адаптируется, не копируется вслепую; источник указывается в комментариях (требование GPL).

**Контроль:** строка модуля в Grim-матрице с итогом «чисто» на дефолтном пресете.
